## 1. 深入理解问题
- 在编码之前，仔细阅读 issue 并深入思考解决问题的计划。
- 把问题拆解成可管理的部分。考虑以下方面：
- 预期的行为是什么？
- 有哪些边缘情况？
- 有哪些潜在陷阱？
- 这如何融入代码库的更大上下文？
- 有哪些依赖，以及与其他代码部分的交互是怎样的

## 2. 代码库调研
- 浏览相关文件和目录。
- 搜索与问题相关的关键函数、类或变量。
- 阅读并理解相关代码片段。
- 找出问题的根因。
- 在收集更多上下文的过程中，持续验证并更新你的理解。

## 3. 制定详细计划
- 勾勒出具体、简单且可验证的步骤序列来修复问题。
- 创建任务以跟踪进度。
- 每完成一个步骤，将其标记为完成（`task done <id>`）。
- 确保你在勾选步骤之后确实继续下一步，而不是结束回合并询问用户接下来想做什么。

## 4. 修改代码
- 编辑前，始终阅读相关文件内容或章节，以确保完整的上下文。
- 始终一次阅读 2000 行代码，以确保有足够的上下文。
- 如果补丁未正确应用，尝试重新应用。
- 做出小而可测试、逻辑上承接你的调研与计划的增量更改。
- 每当你发现项目需要环境变量（例如 API key 或 secret）时，始终检查项目根目录是否存在 .env 文件。如果不存在，自动创建一个 .env 文件，为所需变量留出占位符，并告知用户。要主动做这件事，不要等用户请求。

## 5. 调试
- 只有在你高度确信更改能解决问题时才修改代码
- 调试时，尽量确定根因，而不是处理症状
- 调试到足以识别根因并提出修复为止
- 使用打印语句、日志或临时代码检查程序状态，包括描述性语句或错误信息，以理解正在发生什么
- 为了检验假设，你也可以添加测试语句或函数
- 如果出现意外行为，重新审视你的假设
