使用 BM25 在 markdown 正文上搜索会话/项目/全局记忆。
用它召回此前持久化的内容：项目
记忆、任务叙述（位于 sessions/<sid>/tasks/ 下）、项目
笔记、全局偏好。

记忆布局：<data>/memory/<scope>/<scope_id>/<key>.md
范围：global | projects | sessions | cc（需主动开启，见下文）

查询指南：
- 查询词按 OR 组合并按 BM25 排序：文档只要包含
  任意查询词即匹配，按相关度排序（匹配词的数量/稀有程度）。
  仅命中常见词的低相关度匹配会被
  分数下限丢弃。
- 优先使用 1–3 个有区分度的词（函数名、任务 ID、指令中的
  精确短语、目标片段中的罕见词）。一长串
  泛泛的词（"config params database connection"）只会增加噪声、
  埋没真正的命中——挑选最罕见、最具体的词。
- "T5.3 closure" 有效，"permission deadlock" 也有效。避免用
  泛化描述词填充。
- 标点符号（`.`、`-`、`/`、`:`）在分词时会被剥离。
  query 和索引正文都只看到字母数字串，因此 `T5.3`
  可匹配 `T5.3`、`T5_3` 或 `T5 3`。像 `postgres://host:5433`
  这样的字面量会被索引为 token `postgres`、`host`、`5433`——搜索其中之一，
  而不是完整 URL。

命中结果具有权威性。如果 search 返回了结果，就相信它——即使
你运行的另一个/兄弟查询没有返回任何内容。不要因为
某一种措辞没命中就断定"我从没记录过这个"。

仅有部分命中、但需要精确字面量。命中可能给出了要点，却
遗漏了连接字符串、端口、token、完整
命令行或路径的精确形式（整理时会做改写）。如果你需要
逐字节的字面量，而结果只是近似，请查询 history
工具——search/around 给出摘要，然后 get(part_id) 读取
原文。不要根据改写内容重建或猜测精确值。

当搜索返回 0 时（逐级升级，不要放弃）：
1. 用更少/更罕见的词重试（见上方指南）。
2. 对于分词器会拆开的字面量字符串（URL、端口、路径）——直接在
   记忆目录上使用 Grep 工具；FTS 无法匹配带标点的形式。
3. 对于摘要可能一笔带过的逐字召回——使用
   History 工具：search/around 给出摘要，然后 get(part_id)
   读取原文。
逐步扩大范围：session → project → global → history。

动作：
- search：OR 连接的 BM25 查询，可选 scope/scope_id/type 过滤

search 返回路径后，对最相关的路径使用 Read 工具
加载完整内容（片段会被截断）。如果要按名称模式而非正文查找文件，
可对 `<data>/memory/**/*.md` 使用 Glob 工具
检查目录树。

CC 范围：
当配置中启用 memory.cc_index 时，位于
~/.claude/projects/<slug>/memory/*.md 的 Claude Code 记忆也会以
scope="cc" 索引。scope_id 是 CC 项目 slug（由路径派生的标识符，
如 "-home-user-projects-app"）。frontmatter 的 metadata.type
（feedback / project / reference / user）会填充 type 列，
因此例如 type="feedback" 可过滤 CC feedback 记忆。CC 记忆
通过此工具为只读（read-only）。

隐私说明：CC 的 `type: user` 和 `type: feedback` 类别可能
包含个人上下文（用户角色、偏好、先前指导），
这些内容是 CC 最初为自己未来的会话编写的。开启 cc_index 后，
任何 ymcode 智能体都能召回它们——包括可能接触
提示词注入内容的子代理。如果不希望如此，
请保持 cc_index 关闭，或在搜索时按 `type` 过滤，
排除更敏感的类别。
