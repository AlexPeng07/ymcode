# 中文写作

## 什么时候用

- 写周报、日报、项目进展、复盘
- 写工作邮件、跨团队沟通、对外回复
- 写演讲稿、分享稿、开场白
- 写或改简历、自我介绍
- 整理会议纪要、访谈记录
- 写通知、请示、报告等公文
- 把英文材料、口语记录、零散要点整理成正式中文

不适用：纯翻译（应保留原文结构）、文学创作、代码注释（按代码文档规范处理）。

## 写作前先确认

如果用户没有说明，先问或假设并标注：

1. 文体：周报 / 邮件 / 演讲 / 简历 / 纪要 / 公文
2. 读者：上级、同事、客户、公众
3. 目的：同步、说服、请求、记录、决策
4. 长度与格式：段落 / 列表 / 表格 / 模板

## 通用原则

- 先结论，后背景。第一段回答“发生了什么、需要什么”。
- 动词开头，少用“进行了”“做出了”“关于……方面”。
- 一句话只表达一个意思；长句拆短。
- 数字、时间、负责人、截止日期必须具体。
- 全文统一术语，首次出现可附英文缩写。
- 不堆形容词和排比；删掉“高度重视”“全力以赴”这类空话，除非确有必要。
- 中文标点各司其职：逗号、句号、顿号、分号不要混用。
- 中英文之间是否加空格，全文统一即可。
- 朗读一遍：读起来拗口的地方就是要改的地方。

## 文体模板

### 周报

1. 本周完成：结果 + 数据 + 链接
2. 进行中：当前进度、预计完成时间
3. 风险与阻塞：问题、需要谁支持
4. 下周计划：可验证的产出

不要只列“做了什么”，要写“产生了什么结果”。

### 邮件

- 主题：一句话说明目的，必要时加【需确认】【截止 10/30】
- 称呼：具体到人，避免“各位领导”
- 第一段：结论或请求
- 第二段：必要背景
- 第三段：明确行动项、负责人、截止时间
- 落款：姓名、部门、联系方式

### 演讲稿

1. 开场：问题、故事或反常识结论
2. 主体：三点结构，每点一个例子或数据
3. 结尾：回到开场，给出一个可执行行动

口语化，句子短；每页幻灯片只承载一个观点。

### 简历

- 每条经历用“动词 + 做了什么 + 结果（量化）”
- 优先写与目标岗位相关的项目
- 不写“负责日常开发”这类无法验证的描述
- 技能列表按熟练度排序，不堆关键词

### 会议纪要

- 时间、地点、主持人、参会人
- 议题：每个议题的结论
- 待办：事项 + 负责人 + 截止时间
- 未决问题：需要谁在什么时候决定

纪要只记录结论和行动项，不逐字转录。

## 改写流程

1. 标出结论和行动项
2. 删除重复、套话和无关背景
3. 拆长句，改被动为主动
4. 统一术语、数字格式和标点
5. 检查数字、日期、人名、链接
6. 输出前问自己：读者看完知道下一步做什么吗？

## 输出要求

- 默认给成稿，不写长篇“写作思路”
- 信息不足时用【待补充】标出，不要编造
- 涉及数据、承诺、法律条款时提醒用户核对
- 用户要多个版本时，给“正式版/简短版”各一版，并说明差异
